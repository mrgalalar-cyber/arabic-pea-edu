# منصة التعلّم العربية — دليل الإعداد والنشر

> المعماريّة: واجهة React على **Netlify** + قاعدة بيانات وحسابات وتخزين على **Supabase** + وظائف خلفية (Netlify Functions).
> التفاصيل التقنية في `docs/ARCHITECTURE.md`. اتبع الخطوات بالترتيب؛ أغلبها نقرات في لوحات الخدمات.

## 1) إنشاء الخدمات وربطها

**أ. Supabase** (supabase.com، حساب مجاني)
1. New project → اختر اسمًا وكلمة مرور قاعدة بيانات (احفظها) والمنطقة الأقرب لك.
2. افتح **SQL Editor → New query**، الصق كامل محتوى `supabase/schema.sql` واضغط **Run**. (آمن لإعادة التشغيل.)
3. من **Project Settings → API** انسخ: `Project URL` و`anon public key` و`service_role key` (الأخير سرّي!).

**ب. Netlify** (netlify.com، حساب مجاني)
1. ارفع هذا المجلد إلى مستودع GitHub **خاص** (الملف `.gitignore` يمنع رفع الأسرار).
2. Netlify → Add new site → Import from Git → اختر المستودع. الإعدادات تُقرأ من `netlify.toml` (الأمر `npm run build`، المجلد `dist`).
   لا تستعمل السحب والإفلات: الوظائف الخلفية تحتاج بناءً من Git.

## 2) إدخال مفاتيح البيئة بأمان في Netlify

Site configuration → Environment variables → Add a variable:

| الاسم | القيمة | ملاحظة |
|---|---|---|
| `VITE_SUPABASE_URL` | Project URL | عامّ بطبيعته |
| `VITE_SUPABASE_ANON_KEY` | anon public key | عامّ؛ الحماية في سياسات RLS |
| `SUPABASE_URL` | Project URL | للوظائف الخلفية |
| `SUPABASE_ANON_KEY` | anon public key | للوظائف الخلفية |
| `SUPABASE_SERVICE_ROLE_KEY` | service_role key | **سرّي**: فعّل خيار *Contains secret values* |
| `OWNER_EMAIL` | `mr.galal.ar@gmail.com` | معرّف المالك |

ثم Deploys → Trigger deploy. **لا تضع أي مفتاح في الكود أو المستودع.** (ملف `.env.example` قوالب فارغة فقط.)

## 3) إعداد دخول Google

1. Google Cloud Console → مشروع جديد → **APIs & Services → OAuth consent screen**: النوع *External*، أدخل اسم التطبيق وبريدك. ثم **Publish app** (حتى يستطيع أي طالب الدخول؛ النطاقات الأساسية لا تحتاج مراجعة).
2. **Credentials → Create credentials → OAuth client ID → Web application**. في *Authorized redirect URIs* ضع:
   `https://<معرّف-مشروعك>.supabase.co/auth/v1/callback`
3. انسخ Client ID وClient Secret.
4. Supabase → **Authentication → Sign In / Providers → Google**: فعّله والصق القيمتين.
5. Supabase → **Authentication → URL Configuration**: *Site URL* = رابط موقعك على Netlify. وفي *Redirect URLs* أضف `https://موقعك/auth/callback` (و`http://localhost:5173/auth/callback` للتجربة المحلية).
6. Supabase → **Authentication → Providers → Email**: أبقِه **مفعّلًا** (طلاب الرمز يدخلون عبره داخليًا) وأبقِ **Confirm email** مفعّلًا.

## 4) إعداد بريد المالك

- البريد الافتراضي `mr.galal.ar@gmail.com` موجود في سطر `app_config` داخل `schema.sql` وفي متغير `OWNER_EMAIL`. لتغييره: عدّل المتغير في Netlify، ونفّذ في SQL Editor:
  `update public.app_config set value = 'البريد-الجديد' where key = 'owner_email';`
- **مهم أمنيًا:** بعد أول نشر، ادخل **أنت** فورًا من `/teacher/login` بحساب Google الخاص بالمالك قبل نشر الرابط لأي أحد. المالك لا يُعتمد إلا إذا كان بريده مطابقًا + موثّقًا + مسجّلًا بـ Google فقط (لا هوية بريد/كلمة مرور).

## 5) دعوة المعلمين

1. من القائمة: **المعلمون والدعوات** (للمالك فقط) → **دعوة معلم**.
2. اكتب وصفًا، ويُفضَّل تقييد الدعوة ببريد Google للمعلم، واختر الصلاحية (1–30 يومًا).
3. انسخ الرابط **فورًا** (لا يُعرض ثانية) وأرسله للمعلم. الرابط يعمل مرة واحدة ثم يُستهلك.
4. المعلم المدعو يرى ويدير **فصوله وطلابه وأسئلته وأنشطته ومراجعه فقط**، ولا يستطيع رؤية معلم آخر أو دعواته أو سجل التدقيق. أنت ترى وتدير كل شيء، ويمكنك إيقاف أي معلم فورًا.

## 6) رفع الخطوط

- الخط الافتراضي **تجوّل** (واجهة) و**أميري** (النصوص التعليمية المشكولة) ويُجمَّعان مع الموقع، فلا يلزم شيء.
- لاستخدام خط **ثمانية**: ضع ملف `woff2` في `public/fonts/` (مثلًا `thmanyah.woff2`)، وافتح `public/fonts/fonts.css` وأزل التعليق عن قاعدة `@font-face` وطابق اسم الملف، ثم ادفع التغيير. تأكد أن ترخيص الخط يسمح باستخدامه على الويب. إن لم يصلح الملف فيُكمل الموقع بالخط البديل دون أخطاء.

## 7) إنشاء أول فصل ونشاط

1. **فصولي → فصل جديد**: اكتب الاسم. يُولَّد رمز انضمام (مثل `K7M2QX4P`).
2. داخل الفصل → **إضافة طلاب**: أسماء، اسم في كل سطر (ليختار كل طالب اسمه). 
3. **بنك الأسئلة**: أنشئ سؤالًا (أزرار الحركات أعلى النافذة تُدرج التشكيل)، أو **إضافة أسئلة تجريبية** (موسومة «تجريبي»).
4. **الواجبات والأنشطة → نشاط جديد**: اختر الفصل والأسئلة والقوالب والمواعيد، ثم الحالة **منشور**.
5. أعطِ الطلاب رمز الفصل ورابط الموقع. الطالب: «أنا طالب» → «الانضمام إلى فصل» → رمز الفصل → اسمه → Google أو **رمز ثابت**.
6. **فصولي → الفصل → طلبات الانضمام → موافقة.** يصل الرمز للطالب تلقائيًا على صفحة حالته (مرة واحدة)، ويظهر لك أيضًا. من قائمة الطلاب: زر المفتاح **يستعيد الرمز** لمن فقده أو غيّر جهازه.
7. اطلع على **النتائج** من الأنشطة: ترتيب شفاف يشرح الاحتساب، تصدير CSV، وطباعة/حفظ PDF.

## 8) نشر الموقع وتحديثه

- كل `git push` إلى الفرع الرئيسي ينشر تلقائيًا. التجربة المحلية: `npm install` ثم أنشئ `.env` من `.env.example` ثم `npm run dev` (للوظائف الخلفية محليًا استخدم `npx netlify dev`).
- قبل النشر: `npm test` (45 اختبارًا) و`npm run build`.
- بعد أي تعديل على `schema.sql` شغّل الأجزاء الجديدة في SQL Editor.

## 9) النسخ الاحتياطي واستعادة الأرشيف

- **الأرشيف:** أي «حذف» في المنصة هو أرشفة. من **الأرشيف** استرجع فصولًا/طلابًا/أنشطة/أسئلة/مراجع.
- **نسخة احتياطية:** **الإعدادات → تنزيل نسخة احتياطية** (JSON بكل بياناتك دون رموز الدخول). نزّلها دوريًا: الخطة المجانية في Supabase **بلا نسخ احتياطية تلقائية**. الاستعادة من الملف تتم يدويًا عبر Supabase (Table editor → Import) — لم أبنِ واجهة استيراد بعد.
- **الإيقاف التلقائي:** مشاريع Supabase المجانية **تتوقف بعد أسبوع بلا نشاط** (تُستأنف من اللوحة دون فقد بيانات). في الإجازات الطويلة إمّا تدخل أسبوعيًا أو تنتقل إلى خطة Pro (25$/شهر).

## الحذف التلقائي للتسجيلات الصوتية (3 أشهر)

- كل تسجيل يحمل `uploaded_at` و`delete_after` (= الرفع + 3 أشهر) في جدول `recordings`.
- وظيفة مجدولة `cleanup-recordings` تعمل **يوميًا** على Netlify، وتحذف الملف **فعليًا من التخزين** ثم تُسجّل `deleted_at` (وليس إخفاءً من الواجهة). أي فشل يُسجَّل في `delete_error` ويُعاد في اليوم التالي، وكل تشغيل يُكتب في `audit_log`.
- الحذف اليدوي في أي وقت: إجراء `deleteRecording` في الوظيفة `manage` (يتحقق من أن التسجيل يخص طلاب فصولك).
- **قيود يجب أن تعرفها:** الوظائف المجدولة في Netlify تعمل فقط على نشر الإنتاج الحالي، وزمن التنفيذ في الخطة المجانية نحو 10 ثوانٍ (الوظيفة تعمل بدفعات وتتوقف قبل الحد وتكمل في اليوم التالي)، وتستهلك من رصيد Netlify. تحقّق بعد النشر من Netlify → Functions → `cleanup-recordings` → Logs.
- عند بناء واجهة الرفع (المرحلة 2) سيُعرض للمعلم تاريخا الرفع والحذف المتوقع، وللطالب نص واضح: «سيُحذف تسجيلك تلقائيًا بعد 3 أشهر».

## ملاحظات أمنية

- الصلاحيات والعزل في **قاعدة البيانات** (RLS) وفي الوظائف الخلفية؛ الواجهة للعرض فقط ولا تفيد في التزوير.
- الإجابات الصحيحة لا تصل متصفح الطالب قبل أن يجيب، والتصحيح والنقاط في الخادم. **حدّ:** زمن الإجابة (لنقاط الطاقة) يقيسه المتصفح ويقيّده الخادم بحدود منطقية، فهو غير محصّن تمامًا ضد طالب متمرّس؛ لذا نقاط الطاقة صغيرة ويحدّدها المعلم، والدرجة الأساسية لا تتأثر.
- رمز الفصل يتيح لمن يملكه رؤية **أسماء** الطلاب غير المربوطين في ذلك الفصل (ليختاروا أسماءهم). لا تنشره علنًا. أسماء الطلاب تظهر لزملائهم في لوحات الصدارة داخل الفصل فقط، ويمكن إخفاء اللوحة من إعدادات الفصل.
- رمز الطالب الثابت: 12 رمزًا عشوائيًا (~59 بت)، لا يُخزَّن إلا مُجزَّأً (SHA-256)، مع حدّ للمحاولات. يُحفَظ نصّه مؤقتًا في طلب الانضمام حتى يُسلَّم للطالب مرة واحدة ثم يُمسح.
